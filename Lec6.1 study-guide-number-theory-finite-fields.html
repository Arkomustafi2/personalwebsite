📖 What This Lecture Is Really About

Number theory is the arithmetic engine beneath modern cryptography. Every strong cipher — AES, RSA, elliptic-curve — relies on algebraic structures where addition, multiplication, and inversion are closed, predictable, and computationally hard to reverse without a secret. This lecture builds the mathematical foundation from first principles: divisibility and GCD lead to modular arithmetic, which leads to groups and rings, which lead to finite (Galois) fields — the precise structures AES operates in. The polynomial field GF(2n) is not abstract; it is the byte-level algebra inside SubBytes and MixColumns.

The core takeaway: a Galois field GF(pⁿ) is a finite set where you can add, subtract, multiply and divide — all staying inside the set. That closure under division is what makes crypto math tractable.

Divisibility

Definition of Divisibility KEY

A non-zero integer b divides a (written b | a) if there exists an integer m such that:

a = m × b (a, b, m all integers)

We say b divides into a with no remainder, and call b a divisor of a.

Examples: All of {1,2,3,4,6,8,12,24} divide 24. Also: 13|182, −5|30, 17|289, −3|33, 17|0.

Division Algorithm

For integers a and positive n, there exist unique integers q (quotient) and r (residue) such that:

a = q × n + r where 0 ≤ r < n, q = ⌊a/n⌋

The remainder r is called the residue. This is the foundation for modular arithmetic.

Example: 70 ÷ 15 → 70 = 4×15 + 10. So q=4, r=10.

Greatest Common Divisor (GCD)

GCD Definition KEY

The GCD(a, b) is the largest integer that divides both a and b evenly.

GCD(60, 24) = 12 (largest divisor of both)

Special cases: gcd(0, 0) = 0. When GCD(a,b) = 1, a and b are called relatively prime.

Exam fact: GCD(8,15) = 1, so 8 and 15 are relatively prime. This is essential for modular inverses — an inverse of b mod m exists if and only if GCD(b, m) = 1.

Euclidean Algorithm Algorithm

Uses the key theorem: GCD(a, b) = GCD(b, a mod b). Reduces the problem until remainder = 0.

Euclid(a, b): if b = 0 then return a else return Euclid(b, a mod b)

Extended Euclidean Algorithm KEY

Beyond computing GCD(a,b), the Extended version finds integers x and y such that:

a·x + b·y = d = gcd(a, b)

If GCD(a,b) = 1, then x is the multiplicative inverse of a mod b. This is critical for cryptographic key generation.

EXTENDED_EUCLID(m, b): Initialize: (A1, A2, A3) = (1, 0, m) (B1, B2, B3) = (0, 1, b) Loop: if B3 = 0: return A3 = gcd(m,b), no inverse exists if B3 = 1: return gcd = B3 = 1, B2 = b⁻¹ mod m Q = A3 div B3 (T1, T2, T3) = (A1 − Q·B1, A2 − Q·B2, A3 − Q·B3) (A1, A2, A3) = (B1, B2, B3) (B1, B2, B3) = (T1, T2, T3) goto Loop

Core Definitions

Modulo Operator & Residue KEY

For integer a and positive modulus n, a mod n is the remainder when a is divided by n.

a mod n = r where a = q·n + r, 0 ≤ r ≤ n−1

r is called a residue of a mod n. The set of all residues is Zn = {0, 1, …, n−1}.

Modulo reduction: Different values can have the same residue. E.g.:
−12 mod 7 = −5 mod 7 = 2 mod 7 = 9 mod 7 = 2

Congruence

a and b are congruent modulo n (written a ≡ b mod n) if they have the same remainder when divided by n:

a mod n = b mod n ⟺ n | (a − b)

Example: 100 mod 11 = 1. 34 mod 11 = 1. So 100 ≡ 34 (mod 11).

Modular Arithmetic Rules

Three Fundamental Operations Exam

Reduction can be applied before or after any arithmetic operation:

+

Addition:

(a + b) mod n = [(a mod n) + (b mod n)] mod n

Example: (11+15) mod 8 = 26 mod 8 = 2. [(11 mod 8)+(15 mod 8)] mod 8 = [3+7] mod 8 = 10 mod 8 = 2 ✓

−

Subtraction:

(a − b) mod n = [(a mod n) − (b mod n)] mod n

Example: (11−15) mod 8 = −4 mod 8 = 4. [(3)−(7)] mod 8 = −4 mod 8 = 4 ✓

×

Multiplication:

(a × b) mod n = [(a mod n) × (b mod n)] mod n

Example: (11×15) mod 8 = 165 mod 8 = 5. [(3)×(7)] mod 8 = 21 mod 8 = 5 ✓

Algebraic Structures

Group Exam

A Group G = (S, ·) is a set S with a binary operation · satisfying CAIN:

C

Closure: For all a,b ∈ S, a·b ∈ S

A

Associativity: (a·b)·c = a·(b·c) for all a,b,c ∈ S

I

Identity: ∃ e ∈ S such that e·a = a·e = a for all a ∈ S

N

iNverse: For each a ∈ S, ∃ a⁻¹ ∈ S such that a·a⁻¹ = e

If additionally a·b = b·a (commutativity), the group is called an Abelian group.

Cyclic Group

Exponentiation: Define aᵏ = a·a·…·a (k times). Let e = a⁰ (identity).

A group is cyclic if every element b ∈ G can be expressed as b = aᵏ for some fixed element a and integer k. That fixed element a is called a generator of the group.

Example: Z₇ = {0,1,2,3,4,5,6} under addition mod 7 is cyclic — 1 is a generator (1,2,3,4,5,6,0,1,…).

Ring

A Ring R = (S, +, ×) is a set with TWO operations (addition and multiplication) where:

Under addition:

Forms an abelian group (closure, associative, identity 0, inverse −a, commutative)

Under multiplication:

Closure + Associativity + Distributive over addition: a(b+c) = ab + ac

If multiplication is also commutative → Commutative Ring. If multiplication has an identity and no zero-divisors → Integral Domain.

Field KEY

A Field F = (S, +, ×) has TWO operations where BOTH form abelian groups (the multiplicative group excludes 0). A field satisfies ALL ring properties plus:

M4

Commutativity of multiplication: a×b = b×a

M5

Multiplicative identity: ∃ 1 ∈ F such that 1×a = a

M7

Multiplicative inverse: for each a ≠ 0 ∈ F, ∃ a⁻¹ ∈ F such that a×a⁻¹ = 1

A field is where you can do all four arithmetic operations — add, subtract, multiply, and DIVIDE — without leaving the set. ℝ and ℚ are infinite fields. Cryptography needs finite fields.

Galois Fields

Finite (Galois) Fields KEY

A finite field contains a finite number of elements. It has been proven that:

A finite field must have exactly p^n elements, where p is prime and n ≥ 1.

Finite fields are called Galois fields, denoted GF(pⁿ). The two most important for cryptography are GF(p) and GF(2ⁿ).

Z₈ is NOT a field (8 = 2³ but arithmetic mod 8 doesn't give every element a multiplicative inverse). GF(8) = GF(2³) requires polynomial arithmetic mod an irreducible degree-3 polynomial.

GF(p) — Prime Field

GF(p) is the set {0, 1, …, p−1} with arithmetic operations modulo prime p. Because p is prime, every non-zero element has a multiplicative inverse (found via Extended Euclid). All four operations stay inside the set.

GF(p) forms a finite field — arithmetic is "well-behaved". You can add, subtract, multiply and divide without leaving {0,…,p−1}.

Ordinary Polynomial Arithmetic — Worked Example

Let f(x) = x³ + x² + 2 and g(x) = x² − x + 1

+

Addition: Add corresponding coefficients

f(x) + g(x) = (x³+x²+2) + (x²−x+1) = x³ + 2x² − x + 3
−

Subtraction:

f(x) − g(x) = (x³+x²+2) − (x²−x+1) = x³ + x + 1
×

Multiplication: Distribute every term

f(x) × g(x) = (x³+x²+2)(x²−x+1) = x⁵ − x⁴ + x³ + x⁴ − x³ + x² + 2x² − 2x + 2 ───────────────── = x⁵ + 3x² − 2x + 2

Polynomial Arithmetic mod 2 — Binary Polynomials

Coefficients are in {0, 1} (mod 2). Addition = XOR. Let f(x) = x³+x² and g(x) = x²+x+1:

+

Addition (XOR on coefficients):

f(x) + g(x) = (1·x³ + 1·x² + 0·x + 0) + (0·x³ + 1·x² + 1·x + 1) = x³ + (1⊕1)x² + (0⊕1)x + (0⊕1) = x³ + 0·x² + x + 1 = x³ + x + 1
×

Multiplication: Distribute and reduce coefs mod 2

f(x) × g(x) = (x³+x²)(x²+x+1) = x⁵+x⁴+x³ + x⁴+x³+x² ─────────────── (coefs mod 2) = x⁵ + (1+1)x⁴ + (1+1)x³ + x² = x⁵ + x²

Irreducible Polynomials & Polynomial Division

For any polynomial f(x), we can write: f(x) = q(x)·g(x) + r(x), where r(x) = f(x) mod g(x).

A polynomial g(x) is irreducible (prime) if it has no divisors other than 1 and itself. Arithmetic modulo an irreducible polynomial forms a field.

x³+x+1 is irreducible over GF(2). It is the reducing polynomial for GF(2³) in the slide examples.

Polynomial GCD generalizes the Euclidean algorithm directly:

Euclid(a(x), b(x)): if b(x) = 0 then return a(x) else return Euclid(b(x), a(x) mod b(x))

Computational Example — GF(2³) Arithmetic

In GF(2³): (x²+1) = 101₂ and (x²+x+1) = 111₂

1. Addition:

1

Map polynomials to bit strings: (x²+1) = 101₂, (x²+x+1) = 111₂

2

XOR the bit strings: 101 XOR 111 = 010₂ = x

101 ⊕ 111 ───── 010 → polynomial: x
3

Verify algebraically: (x²+1) + (x²+x+1) = 2x² + x + 2 ≡ 0·x² + x + 0 = x (mod 2) ✓

2. Multiplication of (x+1) × (x²+1):

1

Expand algebraically:

(x+1)(x²+1) = x(x²+1) + 1(x²+1) = x³+x + x²+1 = x³+x²+x+1
2

Verify via bit shift: (x+1) = 011₂, (x²+1) = 101₂

101 << 1 = 1010 (= x³+x) 101 << 0 = 0101 (= x²+1) ───────────────── 1010 XOR 0101 = 1111₂ = x³+x²+x+1
3

Now reduce mod m(x) = x³+x+1 = 1011₂ (degree < 3 must be enforced):

x³+x²+x+1 mod (x³+x+1): = 1·(x³+x+1) + x² → quotient 1, remainder x² i.e.: 1111 XOR 1011 = 0100₂ = x²
(x+1) × (x²+1) = x² in GF(2³) | In bits: 011 × 101 = 100

Using a Generator in GF(pⁿ)

A generator g is an element whose successive powers produce every non-zero element in the field:

GF(pⁿ)\{0} = { g⁰, g¹, g², …, g^{q-2} } where q = pⁿ

A generator can be created from the root of the irreducible polynomial. With a generator, multiplication reduces to adding exponents:

a × b = g^i × g^j = g^{(i+j) mod (q-1)}
This is how fast finite-field multiplication is implemented in practice — precompute a discrete log table, convert to exponents, add, convert back.
