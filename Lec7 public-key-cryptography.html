Study Plan — Public Key Cryptography

What This Lecture Is Really About

Public-key cryptography solves a problem that symmetric cryptography fundamentally cannot: how do two parties establish a secret channel without ever sharing a secret in advance? The answer lies in mathematical trapdoor one-way functions — operations trivial to compute forward, but computationally infeasible to invert without secret information. RSA exploits the hardness of integer factorization; Diffie-Hellman exploits the discrete logarithm problem.

The deeper architectural shift is in the trust model. You no longer need a secure channel to agree on a key — you only need a trustworthy way to publish a public key. This is what enables digital signatures, certificate authorities, TLS, SSH, and the entire security infrastructure of the internet. Understanding RSA and DH at the mathematical level — not just conceptually but numerically — is the goal of this lecture.

Foundations

Public-Key Cryptography: Foundations

Birth of Public-Key Cryptosystems

Beginning → 1960s
Cryptography was entirely based on permutations and substitutions: Caesar cipher, rotor machines (Enigma), DES. All required a pre-shared secret key.
1960s — classified
The NSA secretly discovered public-key cryptography but kept the work classified.
1970
First known (secret) written report on public-key cryptography produced by CESG, UK — still classified.
1976 ← Watershed moment
Diffie and Hellman publicly introduced public-key cryptography. Two revolutionary goals: (1) avoid reliance on third-parties for key distribution, and (2) enable digital signatures for authentication.

Symmetric Cryptography

The same secret key K is used for both encryption and decryption.

C = E(K, M) encrypt M = D(K, C) decrypt Same key K for both operations.
Key distribution problem: how do you securely share K without an already-secure channel? This is a circular dependency.

Asymmetric (Public-Key) Cryptography

One key encrypts, a different but mathematically related key decrypts.

C = E(PU, M) encrypt with public key M = D(PR, C) decrypt with private key
Core requirement: computationally infeasible to determine the private key PR from the public key PU alone — even if you built every computer on Earth.

Public and Private Keys — Full Picture

Every user has a keypair (PUA, PRA). The two keys have dual roles depending on the goal:

KeyVisibilityFor Secrecy (confidentiality)For Authentication
Public Key (PU)Anyone can have itUsed for encryptionUsed for decryption (verification)
Private Key (PR)Owner onlyUsed for decryptionUsed for encryption (signing)
The lecture slide (Slide 4) lists "Private key for authentication: used in decryption" — this appears to be a typo. Slide 6 correctly shows the sender encrypts (signs) with their private key, and the receiver verifies by decrypting with the sender's public key.

🔏 Mode 1: Confidentiality

Goal: only the intended receiver can read the message.

1
Sender A encrypts plaintext M using receiver B's public key PUB:
C = E(PU_B, M)

PU_B is public — anyone can encrypt messages for B.

2
Receiver B decrypts ciphertext using their own private key PRB:
M = D(PR_B, C)
Only the person holding PR_B can decrypt. Even the sender A cannot recover M after encrypting it, since they don't hold PR_B.

✍️ Mode 2: Authentication (Digital Signature)

Goal: prove the message came from a specific sender — non-repudiation.

1
Sender A signs by encrypting with their own private key PRA:
C = E(PR_A, M)

Only A has PR_A, so only A could have produced this ciphertext.

2
Any receiver verifies by decrypting with sender A's public key PUA:
M = D(PU_A, C)

If decryption succeeds and yields coherent plaintext, the signature is verified.

Authentication mode alone does NOT provide confidentiality — anyone with PU_A can decrypt. For both secrecy and authentication, apply double encryption using both keypairs.

Six Requirements of Public-Key Cryptography

1
Easy key generation: Computationally easy for B to generate the keypair (PUb, PRb).
2
Easy encryption: Computationally easy for A, knowing PUb and message M, to generate ciphertext:
C = E(PU_b, M)
3
Easy decryption: Computationally easy for B to decrypt using PRb:
M = D(PR_b, C) = D[PR_b, E(PU_b, M)]
4
Infeasible private key recovery: Given only PUb and C, computationally infeasible for an attacker to determine PRb.
5
Infeasible message recovery: Given only PUb and C, computationally infeasible for an attacker to determine original M.
6
(Optional) Commutativity: Either key applied in either order yields the same result:
M = D[PU_b, E(PR_b, M)] = D[PR_b, E(PU_b, M)]

Trapdoor One-Way Function

The 6 requirements above converge on a single mathematical need: a trapdoor one-way function.

  • • Every function value has a unique inverse
  • • Calculation of the function (forward direction) is easy
  • • Calculation of the inverse is computationally infeasible — unless a secret trapdoor k is known
Y = f_k(X) EASY — if k and X are known X = f_k⁻¹(Y) EASY — if k and Y are known (trapdoor k revealed) X = f_k⁻¹(Y) HARD — if only Y is known (k is secret)
Easy = solvable in polynomial time O(nᵏ) as a function of input size n — the problem scales tractably.
Infeasible = requires super-polynomial (effectively exponential) time — computationally intractable in practice for large n.

Applications of Public-Key Algorithms

Not all algorithms support all three cryptographic operations:

Exam critical: Diffie-Hellman is key exchange ONLY. RSA and ECC are the most versatile (all three uses). DSS handles signatures only.

Three Core Applications of PKC

① Secrecy
Encryption / decryption of messages. Encrypt with receiver's PU; decrypt with receiver's PR. Only the holder of PR can read the message.
② Digital Signature
Sign message with sender's PR. Anyone verifies with sender's PU. Provides authenticity and non-repudiation.
③ Key Exchange
Two parties derive a shared secret key without transmitting it. Used to bootstrap fast symmetric encryption (e.g. AES).
PKC is computationally expensive. In practice it is used for key management and signatures — bulk data encryption uses fast symmetric algorithms (AES) with keys established via PKC.

Public-Key Cryptanalysis — Three Attack Classes

① Brute-Force Attack

Enumerate all possible private keys. Defence: use large keys. Trade-off: larger keys make PKC algorithms computationally heavier. Because of this, public-key algorithms are primarily used for key management and digital signatures rather than bulk encryption.

② Computing Private Key from Public Key

Directly derive PR from PU. There are no known feasible methods on standard (classical) computers — security rests entirely on the hardness of the underlying mathematical problems (integer factorization, discrete logarithm). Quantum computers would break this, which is why post-quantum cryptography is an active research area.

③ Probable-Message Attack

If the message space is small (e.g. a session key, a binary YES/NO, a small integer), an attacker can encrypt all possible messages using the known public key and compare results to the intercepted ciphertext.

1
Attacker knows PUb and intercepted ciphertext C.
2
For each candidate message M', compute C' = E(PUb, M'). Feasible only when M is short.
3
When C' = C, attacker has recovered M.
Countermeasure: Append random bits to M before encryption. Even a short message becomes unpredictable — the search space explodes exponentially. This is the basis of OAEP (Optimal Asymmetric Encryption Padding).
RSA Algorithm

The RSA Algorithm

Overview

Ron Rivest, Adi Shamir, Len Adleman — created in 1978 at MIT. The most widely used public-key algorithm. RSA Security Inc. commercialises related products.

  • • Block cipher: plaintext and ciphertext are both integers in the range [0, n-1]
  • • Supports all three PKC uses: encryption, digital signatures, key exchange
  • • Security based on the computational difficulty of factoring large integers

Key Generation — Step by Step

1
Choose two large distinct primes p and q. Compute:
n = p × q

n is called the modulus. It is public. The primes p and q must remain secret.

2
Compute Euler's totient function φ(n):
φ(n) = (p − 1)(q − 1)

φ(n) counts integers in [1, n-1] coprime to n. This value is kept secret.

3
Select public exponent e such that:
gcd(φ(n), e) = 1 and 1 < e < φ(n)

e must be coprime to φ(n). Popular choices: 3, 17, or 65537. These have few 1-bits in binary, making modular exponentiation faster via square-and-multiply.

4
Compute private exponent d — the modular multiplicative inverse of e:
d ≡ e⁻¹ (mod φ(n)) equivalently: ed ≡ 1 (mod φ(n))

Found using the Extended Euclidean Algorithm. d is kept secret.

Public Key: PU = { e, n } Private Key: PR = { d, n } (p, q also private)
n and e are public. p, q, and d are PRIVATE. Anyone can compute n = pq, but reversing it (factoring) is computationally infeasible for large primes.

🔒 Encryption

Plaintext M must satisfy M < n.

C = Mᵉ mod n

Raise plaintext to the public exponent e, take result modulo n. Anyone can encrypt using the public key {e, n}.

🔓 Decryption

Given ciphertext C:

M = Cᵈ mod n

Raise ciphertext to the private exponent d, take modulo n. Only the holder of d can recover M.

Requirements of the RSA Algorithm

1
Possible to find e, d, n such that:
Mᵉᵈ mod n = M for all M < n

Guaranteed by Euler's theorem when ed ≡ 1 (mod φ(n)) and gcd(M, n) = 1.

2
Easy to compute Mᵉ mod n and Cᵈ mod n for all M < n.

Achieved via fast square-and-multiply modular exponentiation in O(log e) multiplications.

3
Computationally infeasible to determine d given only e and n.

This requires factoring n = pq, hard for large primes. No polynomial-time classical algorithm known.

Requirements met when:
n = pq, 1 < e < φ(n), ed ≡ 1 (mod φ(n)), d ≡ e⁻¹ (mod φ(n))

RSA Implementation Parameters (PKCS#1 / CRT Format)

In practice, the private key structure includes additional Chinese Remainder Theorem parameters for efficient decryption — roughly 4× speedup:

ParameterSymbolValue / DefinitionVisibility
Modulusnn = p × q, length b bitsPublic
Public exponentegcd(e, φ(n)) = 1; typically 65537Public
Private exponentdd ≡ e⁻¹ (mod φ(n))Private
Prime 1pFirst large prime factorPrivate
Prime 2qSecond large prime factorPrivate
CRT Exponent 1dpdp = d mod (p − 1)Private
CRT Exponent 2dqdq = d mod (q − 1)Private
CRT Coefficientqinvqinv = q⁻¹ mod pPrivate
Private values: { n, e, d, p, q, d_p, d_q, q_inv } Public values: { n, e }
CRT decryption computes Cᵈ mod p and Cᵈ mod q separately (using d_p and d_q), then combines with q_inv using the CRT. This is ~4× faster than naively computing Cᵈ mod n.

Computational Efficiency of RSA

Encryption and decryption both require large-number modular exponentiation. Key modular arithmetic identity:

[(a mod n) × (b mod n)] mod n = (a × b) mod n

This allows numbers to be kept small at every intermediate step (no astronomical intermediates).

Choosing e

3, 17, and 65537 are popular — few 1-bits in binary representation → fewer multiplications in square-and-multiply. Small e is faster to encrypt but vulnerable to attack: countermeasure is random padding on M before encryption.

Choosing d

Small d is also vulnerable. Decryption with large d is accelerated using Chinese Remainder Theorem (CRT) and Fermat's Little Theorem. This is why the CRT parameters are included in the private key structure.

Choosing p and q

Must be very large primes. Practical method: generate a large random odd number, then test primality using a probabilistic Miller-Rabin test. Repeat until a prime is found. The probability of error is made negligibly small by running multiple rounds.

Security of RSA

① Brute-Force

Try all possible d values. Defence: choose large d (and thus large n). Trade-off: slower decryption.

② Mathematical Attacks (Three Approaches)

A
Factor n into p and q. Then compute φ(n) = (p-1)(q-1) and derive d. This is the fastest known mathematical approach and is used as the measure of RSA security.
B
Determine φ(n) directly without factoring p and q. Then derive d from ed ≡ 1 (mod φ(n)).
C
Determine d directly without finding φ(n). No known efficient method.
Factoring n is considered the fastest mathematical attack on RSA. RSA key size is chosen to make factoring computationally infeasible — currently ≥ 2048 bits recommended.

③ Timing Attacks

Measure how long decryption takes for different ciphertexts — timing correlates with the bits of d. Countermeasures: add constant-time implementations or random delay. Performance penalty: only 2–10%.

④ Chosen Ciphertext Attack

Attacker submits crafted ciphertexts to a decryption oracle and uses the responses to extract information about d. Countermeasure: OAEP (Optimal Asymmetric Encryption Padding) — adds randomness and structural constraints that make this attack infeasible.

Diffie-Hellman · Key Exchange

Diffie-Hellman Key Exchange

Overview

Diffie and Hellman proposed the public-key cryptosystem in 1976. DH is an algorithm for exchanging a secret key — not for encrypting or signing data directly.

Mathematical basis: Discrete logarithm problem. Easy: compute αˣ mod q (exponentiation). Hard (infeasible): given αˣ mod q, find x — this is the discrete log.
Purpose: Allow two parties to establish a shared secret K over a completely public, untrusted channel. K is then used to key a fast symmetric cipher (AES) for actual data encryption.

Diffie-Hellman Algorithm

Global Public Elements — agreed by both parties, publicly known

ElementConstraintRole
qLarge prime numberThe modulus for all computations
αα < q; α is a primitive root of qThe base/generator

User A — Key Generation

1
A selects a private integer XA where XA < q (kept strictly secret).
2
A computes and publishes:
Y_A = α^(X_A) mod q

User B — Key Generation

1
B selects a private integer XB where XB < q (kept strictly secret).
2
B computes and publishes:
Y_B = α^(X_B) mod q

Computing the Shared Secret Key

A
A computes shared key using B's published value:
K = (Y_B)^(X_A) mod q
B
B computes shared key using A's published value:
K = (Y_A)^(X_B) mod q
Why both formulas yield the same K:
(Y_B)^(X_A) mod q = (α^X_B)^X_A mod q = α^(X_A · X_B) mod q (Y_A)^(X_B) mod q = (α^X_A)^X_B mod q = α^(X_A · X_B) mod q ∴ Both parties arrive at the same shared secret: K = α^(X_A · X_B) mod q
An eavesdropper sees q, α, Y_A, Y_B — but finding X_A from Y_A = α^X_A mod q requires solving the discrete logarithm. No feasible classical algorithm exists for large q.

🔢 Worked Numerical Example

Using q = 23, α = 5 (5 is a primitive root of 23), XA = 6, XB = 15:

StepOperationResult
Global setupq = 23, α = 5Publicly known to everyone
A's private keyXA = 6Secret to A only
B's private keyXB = 15Secret to B only
A's public valueYA = 5⁶ mod 23 = 15625 mod 23= 8 (published)
B's public valueYB = 5¹⁵ mod 23= 19 (published)
A computes KK = (YB)^XA mod 23 = 19⁶ mod 23= 2
B computes KK = (YA)^XB mod 23 = 8¹⁵ mod 23= 2
Shared secret KK = 2 ✓ — both agree
An attacker sees q=23, α=5, Y_A=8, Y_B=19 — to find X_A=6 they must solve 5^x ≡ 8 (mod 23). This is the discrete logarithm — infeasible at scale.
Verification of Y_B=19: 5¹⁵ mod 23. Note 5²=25≡2, 5⁴≡4, 5⁸≡16, 5¹⁵ = 5⁸·5⁴·5²·5¹ = 16·4·2·5 = 640. 640 mod 23 = 640 − 27×23 = 640 − 621 = 19 ✓

Security of Diffie-Hellman

Critical vulnerability: Man-in-the-Middle (MitM) Attack. DH has NO built-in authentication. An attacker (Mallory) sitting between A and B can: intercept Y_A, send their own Y_M to B; intercept Y_B, send their own Y_M' to A. Mallory maintains two separate DH sessions — one with A and one with B. A and B believe they have a shared secret, but Mallory is decrypting and re-encrypting everything.
Countermeasure: Use digital signatures + public-key certificates (PKI). Each party signs their DH public value Y with their certified private key. The other party verifies against a trusted Certificate Authority. This is exactly how TLS (HTTPS) works — ECDHE for key exchange, RSA/ECDSA certificates for authentication.

ElGamal Cryptosystem

Based on the same discrete logarithm hardness as Diffie-Hellman.

  • • Used in the Digital Signature Standard (DSS)
  • • Used in secure email systems (e.g. GPG/PGP)

Elliptic Curve Cryptography (ECC)

Uses elliptic curve arithmetic instead of modular arithmetic — operating over points on an elliptic curve defined over a finite field.

  • • Same security as RSA with much smaller keys → better performance
  • • 256-bit ECC ≈ 3072-bit RSA in security strength
  • • ECDH for key exchange, ECDSA for digital signatures
ECC is now the preferred choice for TLS, mobile, and IoT — smaller keys mean less bandwidth, less computation, less energy.

Extended Euclidean Algorithm — Finding d

To find d = e⁻¹ mod φ(n), use the Extended Euclidean Algorithm which finds x, y such that ax + by = gcd(a, b):

1
Run Euclidean algorithm on gcd(e, φ(n)) — must confirm gcd = 1.
2
Back-substitute to express 1 as a linear combination:
1 = x·e + y·φ(n)
3
Then x mod φ(n) is the modular inverse d. If x is negative, add φ(n).
Worked example — e=3, φ(n)=20:
Division steps: 20 = 6×3 + 2 3 = 1×2 + 1 2 = 2×1 + 0 → gcd = 1 ✓ Back-substitution: 1 = 3 − 1×2 = 3 − 1×(20 − 6×3) = 7×3 − 1×20 ∴ d = 7 (x = 7 in 7×3 + (−1)×20 = 1) Verify: 3 × 7 = 21 = 1 + 1×20 ≡ 1 (mod 20) ✓

Square-and-Multiply — Fast Modular Exponentiation

Computing Mᵉ mod n naively for large e is infeasible. The binary method keeps numbers small at every step:

Compute 4³ mod 33: Binary representation of e=3 → 11₂ (bits from MSB to LSB) result = 1 Bit '1' (MSB): result = (1² × 4) mod 33 = 4 Bit '1' (LSB): result = (4² × 4) mod 33 = (16 × 4) mod 33 = 64 mod 33 = 31 ∴ C = 31
Square-and-multiply requires at most 2·log₂(e) multiplications. For e = 65537 (2¹⁶ + 1), only 17 squarings and 1 multiplication are needed — very efficient.

RSA Round-Trip Verification — Why it Works

The correctness of RSA follows from Euler's Theorem: if gcd(M, n) = 1, then:

M^φ(n) ≡ 1 (mod n)

Since ed ≡ 1 (mod φ(n)), we can write ed = 1 + k·φ(n) for some integer k. Then:

M^(ed) = M^(1 + k·φ(n)) = M · (M^φ(n))^k ≡ M · 1^k ≡ M (mod n)
So decrypting the ciphertext gives back the original plaintext: D(PR, E(PU, M)) = M^(ed) mod n = M. The mathematical elegance of RSA is that encryption and decryption are inverse operations via Euler's theorem.
