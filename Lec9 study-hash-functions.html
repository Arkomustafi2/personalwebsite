Overview

What This Lecture Is Really About

A cryptographic hash function maps an arbitrarily long input to a fixed-size digest — and does so in a way that is computationally impossible to reverse or collide. This lecture builds that idea from first principles: why hash functions are useful for authentication, what mathematical properties they must satisfy, how those properties are attacked (especially the distinction between 2m pre-image effort and 2m/2 collision effort due to the birthday paradox), and why that gap drives real algorithm choices like abandoning MD5 in favour of SHA-256.

The lecture also covers how hash functions combine with symmetric encryption and public-key cryptography to produce message authentication protocols and digital signatures. The four configurations (a–d) from Stallings Fig. 11.2 and the digital signature formula S = E(PRA, H(M)) are high-frequency exam topics.

Key exam points: (1) 6 requirements of a cryptographic hash function, (2) why collision effort = 2m/2 not 2m (birthday paradox), (3) four message authentication protocol diagrams, (4) digital signature formula S = E(PRA, H(M)), (5) which hash properties each application requires (Table 11.2).

Definition

What is a Hash Function?

A hash function H takes a variable-length block of data M and produces a fixed-size hash value h:

h = H(M) M = input message (any length) h = hash value / digest (fixed n bits) H = the hash function

Applying H to a large set of inputs should produce evenly distributed and random-looking outputs. Used to determine whether data has changed.

Applications: message authentication · digital signatures · one-way password files · intrusion/virus detection · PRNG

Weak hash function: Satisfies requirements 1–5 only (not collision resistant). Sufficient for some applications like hash + symmetric encryption.

Pre-images and Collisions

Pre-image Mathematics Exam

1

Pre-image: For hash value h = H(x), x is a pre-image of h. Because H is many-to-one, every hash value has multiple pre-images.

2

Collision: Occurs when x ≠ y but H(x) = H(y). Collisions are undesirable — an attacker who finds one can substitute a malicious message for a legitimate one with the same hash.

3

Counting pre-images: If H takes b-bit input blocks and produces n-bit hash codes (where b > n):

Input space: 2^b possible messages Hash space: 2^n possible hash codes Average pre-images per hash value: 2^b / 2^n = 2^(b-n) Example: SHA-256 (b=512-bit blocks, n=256-bit hash) Each hash has avg 2^(512-256) = 2^256 pre-images Finding one specific pre-image: still 2^256 operations
Having many pre-images per hash does NOT make them easy to find. Pre-image resistance guarantees it remains infeasible regardless of how many pre-images exist.

Message Authentication

Four Hash-Based Authentication Protocols Exam

A hash function used to provide message authentication is called a message digest. It verifies data integrity and sender identity. Four configurations from Stallings Fig. 11.2:

(a) Encrypt Message and Hash — Full Confidentiality + Auth

Source A: M ──► H(M) ──► [M || H(M)] ──► E(K, [M || H(M)]) ──► Channel Receiver B: Decrypt with K → get M and H(M) → recompute H(M) → Compare ✓ Transmitted: E(K, [M || H(M)]) Provides: Confidentiality + Source Auth + Data Auth Note: both message AND hash are encrypted together.

(b) Encrypt Only Hash — Auth Without Full Confidentiality

Source A: M sent in clear M ──► H(M) ──► E(K, H(M)) ────────────────────────► Channel Receiver B: Receives M (clear) + E(K,H(M)), decrypt tag → H(M), recompute H(M) → Compare ✓ Transmitted: M || E(K, H(M)) Provides: Source Auth + Data Auth (NO confidentiality) Benefit: Reduces computation when confidentiality is not required.

(c) Hash With Shared Secret — No Encryption Needed

Source A: [M || S] ──► H(M || S) Send M and H(M || S) — no encryption ──────────────► Channel Receiver B: Appends shared secret S to received M, recomputes H(M||S) → Compare ✓ Transmitted: M || H(M || S) Provides: Source Auth + Data Auth (NO confidentiality) Key insight: S is never sent. Only someone who knows S can produce valid H(M||S).

(d) Shared Secret Combined With Confidentiality

Source A: [M || S] ──► H(M||S) ──► [M || H(M||S)] ──► E(K, [M || H(M||S)]) Receiver B: Decrypt → M and H(M||S) → recompute H(M||S) with S → Compare ✓ Transmitted: E(K, [M || H(M || S)]) Provides: Confidentiality + Source Auth + Data Auth (strongest configuration)
Why avoid encryption for authentication? Software encryption is slow · Hardware encryption has financial costs and may be inefficient for small data · Encryption algorithms may be patented · For auth-only needs, configurations (b) and (c) are preferred.
Digital Signatures

Why Public Key is Needed Exam

Symmetric Key — No Non-repudiation

✗

A and B share secret key K. A can verify message came from B. But third-party C cannot prove it came from B specifically — it may also have come from A. No third-party verifiability.

Public Key — Full Non-repudiation

✓

Only A holds private key PRA. Anyone with A's public key PUA can verify the signature. Even user C can independently verify the message came from A — provides non-repudiation.

Digital Signature Operations

Concept vs. Practice Must Memorise

Conceptual (sign entire message)

Signing: S = E(PR_A, M) (encrypt whole M with private key) Verification: M' = D(PU_A, S) If M' = M → verified ✓ Problem: expensive — must encrypt the entire (possibly large) message.

Practical (sign hash of message)

Signing: S = E(PR_A, H(M)) (encrypt hash of M with private key) Verification: h = D(PU_A, S) Compute H(M) from received M. If H(M) = h → verified ✓ Advantage: hash is fixed small size (e.g. 256 bits) regardless of M.
Why hash before signing? Public-key operations (RSA, ECDSA) are expensive. Hashing first reduces M to a fixed small digest which is then signed. The hash guarantees that any change to M is detectable.

Brute Force Attacks

Two Fundamentally Different Attack Types Exam

Pre-image and 2nd Pre-image Attack

Goal

Find y that produces a specific target hash h. Either H(y) = h (pre-image) or given x, find y ≠ x with H(y) = H(x) (2nd pre-image).

How

Try all possible values of y. Must try approximately 2m inputs before finding a match in an m-bit hash space.

∴
Effort ∝ 2^m

Collision Resistant Brute Attack

Goal

Find any two messages with the same hash — no specific target. Just find any x ≠ y with H(x) = H(y).

Why Easier

Due to the birthday paradox, finding any two matching values only requires approximately 2m/2 trials — far fewer than 2m.

∴
Effort ∝ 2^(m/2)
Critical implication: MD5 (128-bit hash) provides only 264 collision resistance. Practical collision attacks have been demonstrated at 260 operations — trivially achievable today. MD5 is broken for security use.
Birthday Paradox

Why Collisions Are Found So Much Faster Exam

🎂

Real-world birthday paradox: In a room of 23 people, the probability two share a birthday exceeds 50%. Seems surprising since 23 is much smaller than 365. The key: each new person can potentially match any of the previous people — there are C(23,2) = 253 potential pairs.

H

Applied to hash collisions: In an m-bit hash space (2m values), after generating approximately 2m/2 random messages, the probability that two share the same hash exceeds 50%. Each new message can match any previously computed hash.

Birthday Bound Analysis: Hash size: m bits → 2^m possible hash values Probability of at least 1 collision after k messages: P(collision) ≈ 1 − e^(−k² / 2^(m+1)) P > 0.5 when k ≈ 2^(m/2) MD5 (m=128): collision threshold ≈ 2^64 → BROKEN (practical at 2^60) SHA-1 (m=160): collision threshold ≈ 2^80 → BROKEN (SHAttered, 2017) SHA-256 (m=256): collision threshold ≈ 2^128 → Currently infeasible SHA-512 (m=512): collision threshold ≈ 2^256 → Infeasible, high-security use

Practical Notes

Cryptanalysis vs. Brute Force

→

Cryptanalysis attacks exploit structural weaknesses in specific algorithms. They can dramatically reduce effort below the birthday bound — as happened with MD5 (birthday = 264, practical attacks at 260).

→

Collision resistance is the most desirable property for general hash algorithms. It implies second pre-image resistance and is harder to achieve.

✓

SHA-256 and SHA-3: No known practical collision attacks. Collision attacks on either are computationally infeasible with all currently foreseeable hardware advances.

MD5

Message Digest 5 Deprecated

📅

Developed by Ron Rivest at MIT in 1991

📄

Standardised by IETF in RFC 1321

n

Generates a 128-bit (16-byte) hash digest

!

Was widely used for passwords, file integrity, and certificates. No longer recommended. Collision and other attacks are possible. Public tools exist.

!

128-bit → birthday collision at 264, but practical attacks demonstrated at ≈260. Do not use for digital signatures, certificates, or password storage.

SHA Family

Secure Hash Algorithm NIST Standard

📋

Developed by NIST. Standardised in FIPS 180 in 1993. Improved over time: SHA-0 → SHA-1 → SHA-2 → SHA-3.

!

SHA-1 and SHA-0 are insecure — no longer recommended. Google demonstrated a SHA-1 collision in 2017 (SHAttered attack, costing ~110 GPU-years).

✓

SHA-3 was selected via open NIST competition (Keccak algorithm won). Uses sponge construction — fundamentally different architecture from SHA-2. Both SHA-2 and SHA-3 are currently secure.
