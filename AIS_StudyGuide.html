📌 What This Course Is Really About

This module covers the foundational architecture of intelligent systems — starting from the formal definition of an agent (anything that perceives and acts) and the five canonical agent types (Simple Reflex through Learning), all framed by the PEAS model. The second half pivots to search: how an agent systematically finds solutions in a state space, covering both uninformed strategies (BFS, DFS, DLS, IDDFS, UCS) and informed strategies that exploit heuristics (Greedy Best-First, A*). The module closes with a brief treatment of Genetic Algorithms as a population-based optimization method. The unifying thread is rationality — every design choice, from choosing a queue type to defining admissibility, is about maximising the agent's performance measure.

🤖 What Is an Agent?

An agent is anything that can be viewed as:

  • Perceiving its environment through sensors
  • Acting upon that environment through actuators

Human Agent

Sensors Eyes, ears, other organs

Actuators Hands, legs, mouth, other body parts

Robotic Agent

Sensors Cameras, infrared range finders

Actuators Various motors

Software Agent

Sensors Keystrokes, file contents, received network packets

Actuators Display on screen, files, sent network packets

Goal

We want it to be a machine that can automatically sense and act — i.e., Agent → Percept → Decision → Actions (to change environment)

📥 Percept & Percept Sequence

Percept

The agent's perceptual input at any given instant. The single snapshot of what the sensors currently detect.

Percept Sequence

The complete history of everything the agent has ever perceived. Used by the agent function to decide actions.

Key Principle An agent's behaviour is described by the agent function, which maps from percept histories (P*) to actions (A):
f : P* → A
Internally, this function is implemented by an agent program running on a physical architecture to produce f.

⚖️ Rational Agent

A rational agent is one that can take actions to maximise its performance measure based on:

  • The perceived sequence to date
  • Prior knowledge of the environment
🎓 Exam Definition "A rational agent is an agent which can do the right action to maximise performance measure based on the perceived sequence to date and prior knowledge of the environment."

Performance Measure

An objective criterion for the success of an agent's behaviour. The right action is the one that will cause the agent to be most successful.

⚠️ Distinction Rationality ≠ omniscience. A rational agent maximises expected performance given what it can perceive and do — it doesn't require perfect knowledge.

Goals of an Agent

  • High performance
  • Optimised result
  • Rational (right) action

🗺️ State Space Search — Formulation

A state space search goes from an initial state to a goal state through intermediary steps, comparing each intermediary step state with the goal state.

Problem = {S, A, Action(s), Result(s,a), Cost(s,a)} S = Set of all possible states A = Set of actions Action(s) = Actions applicable in state s Result(s,a) = State resulting from action a in state s Cost(s,a) = Step cost for action a in state s

8-Puzzle Example

The empty tile can move: up, down, left, right. Start state is scrambled; goal is sorted arrangement. Each branch is a move.

Types of Searching

Uninformed (Blind) Only start and goal state are known. Examples: BFS, DFS, DLS, IDDFS, UCS
Informed (Heuristic) Additional domain knowledge used. Examples: Greedy Best-First, A*, and its variants

Problem-Solving Performance Metrics

MetricMeaning
CompletenessYes/No for whether a solution will always be found if one exists
OptimalityIs the solution found the optimal one based on cost function?
Time ComplexityTime to run the algorithm (nodes expanded)
Space ComplexityMemory (RAM) required for the algorithm (nodes stored)

🌊 Breadth First Search (BFS) — Uninformed

Simple strategy in which the root node is expanded first, then all the successors of the root node, next their successors, and so on. Expand shallowest unexpanded node.

Data Structure

Fringe = FIFO Queue New nodes added to the tail; expanded from the head. This guarantees level-by-level (breadth-first) exploration.

Tree:                           A (d=0)
                              / | \
                            B   C   D   (d=1)
                           / \ / \   \
                          E  F G  H   I  (d=2)
                         / \         |
                        J   K        M  (d=3)
                       /
                      N  (d=4)
StepNode ExpandedQueue After ExpansionNotes
1A[B, C, D]Root expanded; depth 0
2B[C, D, E, F]B's children E,F added
3C[D, E, F, G, H]C's children G,H added
4D[E, F, G, H, I]D's child I added
5E[F, G, H, I, J, K]E's children J,K added
6F[G, H, I, J, K]F is leaf
7G[H, I, J, K]G is leaf
8H[I, J, K]H is leaf

Properties

1. Completeness Always finds a solution if one exists (level-wise complete, shallowest→nearest node)
2. Optimality Optimal if all actions have the same cost (finds shallowest goal first)
Time Complexity : O(b^d) Space Complexity : O(b^d) b = branching factor (max successors) d = depth of shallowest solution
🎓 Exam: Why does BFS use O(b^d) space? It must keep all nodes in the fringe (queue) — at depth d there are b^d nodes, all stored simultaneously.

🌲 Depth First Search (DFS) — Uninformed

Expands the deepest unexpanded node and does backtracking after reaching the deepest leaf node.

Fringe = LIFO Queue (Stack) Put successors at front (top of stack). Last In, First Out.

DFS Traversal Order (Example)

Tree: A → B → D → H → I → J → E → K → C → F → G (goal) → M → N → D (revisit warning)

DFS Stack trace (each column = stack contents):
[A] → [B,C] → expand B: [D,E,C] → expand D: [H,I,E,C] → expand H: [I,E,C]
→ expand I: [J,E,C] → expand J: [E,C] → expand E: [K,C] → expand K: [C]
→ expand C: [F,G] → expand F: [G_n,G] → ...

Properties

#PropertyValueReason
1Completeness❌ IncompleteNot complete in infinite depth spaces (with loops) — may go forever on one branch
2Optimality❌ Not optimalMay find a deep (non-optimal) solution first
3TimeO(b^m)b = branch factor, m = max depth
4SpaceO(b·m) = linearOnly stores current path + siblings — far better than BFS
⚠️ Infinite node problem If there are infinite nodes in the tree, DFS cannot come back. This is why DLS and IDDFS were developed.

Key advantage over BFS: Linear space O(bm) vs O(b^d). Critical for deep state spaces.

✂️ Depth Limited Search (DLS)

A variant of DFS that imposes a limit (L) on the depth of the search tree. Particularly used in problems where the search space is vast or infinite.

Motivation In DFS, on an infinite space with nodes, the goal state may have an infinite number of nodes to traverse, causing infinite loops. So we limit the depth to L (e.g., 3 or 5), so each node has depth ≤ L and we can find the goal faster.

Key Points

1
The primary characteristic of DLS is the depth limit (L). The algorithm explores the search tree only up to the specified depth.
2
DLS is incomplete if the solution exists beyond the depth limit — it will miss it entirely.
3
Time complexity: O(b^L) where b = branching factor, L = depth limit.
4
Space complexity: O(L) — linear in depth limit (like DFS).
5
DLS is not optimal — does not guarantee the shortest path if multiple solutions exist within limit.
🎓 Exam Comparison: DFS vs DLS DFS has no depth bound (may loop forever on infinite graphs). DLS adds a hard cutoff at depth L, preventing infinite loops but potentially missing solutions deeper than L.

🔄 Iterative Deepening DFS (IDDFS)

Combines the benefits of DFS and BFS. Searches to a limited depth, increasing the limit with each iteration. Ensures exploration of all nodes at each depth before going deeper.

Key Properties
  • ✅ Complete (like BFS)
  • ✅ Optimal (finds shallowest solution first)
  • ✅ Linear Space O(bd) (like DFS)
  • ⚠️ Does redundant work: nodes at shallow depths are expanded multiple times

Worked Example — Iteration Trace

Iteration (I)Depth Limit (d)Nodes Visited
I = 0d = 0A
I = 1d = 1 (limit increases)A → B → C → D
I = 2d = 2 (limit +1)A → B → E → F → C → G → H → D → I (Goal found!)

At I=2, DFS-style traversal is done but depth ≤ 2 is enforced. Once I reaches goal depth, search succeeds. Nodes like A, B, C, D at shallow depths are re-expanded at each iteration (redundant work) — but this is a small constant factor.

Why is redundant work acceptable? Most nodes are at the deepest level — in a tree with branching factor b and goal at depth d, the fraction of work at the last level is (1 - 1/b), which approaches 1 for large b. So re-expanding shallower nodes costs relatively little.

IDDFS vs BFS vs DFS — Final Comparison

AlgorithmCompleteOptimalTimeSpace
BFS✅✅ (uniform cost)O(b^d)O(b^d)
DFS❌❌O(b^m)O(bm)
DLS (limit L)❌ (if sol > L)❌O(b^L)O(L)
IDDFS✅✅O(b^d)O(bd)
🎓 Why IDDFS is preferred in practice It gets BFS's completeness and optimality with DFS's linear space. The overhead from re-expansion is usually a constant factor (e.g., ×b/(b-1)) which is small for large branching factors.

💰 Uniform Cost Search (UCS)

An uninformed search strategy that expands the node with the lowest cumulative cost from the start node. Each link has a length/cost (always > 0).

Key Idea
  • We want the shortest / least-cost path
  • Fringe = Queue ordered by path cost g(n)
  • Equivalent to BFS if all step costs are equal
  • Expands least-cost unexpanded node

💡 Heuristics in AI — "Rule of Thumb"

A heuristic is a technique designed to solve a problem quickly when standard methods are too slow. It reduces time complexity but is not sure about optimality.

Why Heuristics?

  • Exponential complexity of uninformed search is impractical for large problems
  • Domain knowledge can guide the search toward the goal
  • Trade-off: speed vs guaranteed optimality

Euclidean Distance (common heuristic)

h(n) = √[(x₂-x₁)² + (y₂-y₁)²] Straight-line distance from node n to the goal state G — minimal distance
Heuristic Function h(n) Estimates the cost of the cheapest path from node n to a goal node. In Best-First Search, the heuristic value determines the path/priority used to enter the queue.

🤑 Greedy Best First Search

Expands the node that appears to be closest to the goal. Based entirely on heuristic value (greedy — only cares about estimated cost to goal, ignores cost so far).

Evaluation function: f(n) = h(n) h(n) = estimated cost from n to goal = straight-line distance from n to goal

⭐ A* Search

A search algorithm in which the node with the least f(n) value is expanded first. Combines actual cost so far with estimated cost to goal.

🎓 Core Formula
f(n) = g(n) + h(n) g(n) = cost so far to reach n (actual cumulative path cost) h(n) = estimated cost from n to goal (heuristic) f(n) = estimated total cost of path through n to goal

Why A* Works — Intuition

At each step, A* picks the node with lowest total estimated cost: actual cost already paid + optimistic estimate of remaining cost. By never overestimating (admissibility), it guarantees finding the true optimal path.

A* Properties

1. Complete : Always finds a solution if one exists 2. Optimal : Finds the best (lowest-cost) solution 3. Time : Exponential in worst case (#nodes with cost + h < goal cost) 4. Space : Keeps all nodes in memory (exponential worst case)

🎯 Admissible Heuristics

A heuristic h(n) is admissible if for every node n:

h(n) ≤ h*(n) where h*(n) = true (optimal) cost to reach goal from n
🎓 What admissibility means An admissible heuristic never overestimates the cost to reach the goal. It is optimistic — it thinks the cost of solving the problem is less than it actually is. This ensures A* never "gives up" on the optimal path prematurely.

Optimality of A* (Tree Search) — Proof Sketch

Theorem: If h(n) is admissible, A* using TREE SEARCH is optimal.
1
Suppose some suboptimal goal G₂ has been generated and is in the fringe. Let the cost of the optimal solution to goal G₁ be C*.
2
Since G₂ is suboptimal: g(G₂) > C*
3
Let n be a node on the optimal path to G₁ that is still in the fringe. Then: f(n) = g(n) + h(n) ≤ g(n) + h*(n) = C* (by admissibility)
4
For G₂ (a goal): f(G₂) = g(G₂) (since h(G₂) = 0 for a goal node)
5
Therefore: f(G₂) = g(G₂) > C* ≥ f(n)
6
Conclusion: A* will expand n before G₂, so it will never expand a suboptimal goal. QED.
Summary of key steps: f(G₂) = g(G₂) since h(G₂) = 0 g(G₂) > C* since G₂ is suboptimal f(n) ≤ C* by admissibility of h ∴ f(G₂) > f(n) → A* expands n first → optimal goal found first

🧬 Genetic Algorithm (GA)

A population-based evolutionary optimization technique inspired by the principles of natural selection and genetics. Works by iteratively evolving a population of candidate solutions using biologically motivated operators.

Core Operators

  • Selection: Choose fitter individuals to reproduce
  • Crossover: Combine genetic material from two parents to produce offspring
  • Mutation: Apply random changes to offspring genes to maintain diversity
Fitness Function Acts as the guiding force — determines which individuals are more likely to reproduce. Evaluates solution quality.

Step-by-Step Explanation

StepNameDescription
1Population InitializationGenerate initial population of chromosomes randomly within problem constraints
2Fitness EvaluationEvaluate each chromosome using the fitness function to measure solution quality
3Parent SelectionSelect parent chromosomes based on fitness using methods like Roulette Wheel Selection (higher fitness → higher probability of selection)
4CrossoverCombine genetic material from selected parents to produce offspring (e.g., single-point crossover splits chromosomes at a random point and swaps segments)
5MutationApply random changes to offspring genes to maintain diversity and prevent premature convergence to local optima
6New Generation FormationReplace the old population with newly generated offspring
7Termination CheckIf stopping criterion met (max generations, fitness threshold, convergence) → output best solution. Else → repeat from step 2.
🎓 GA vs Traditional Search GA searches in parallel (population-based, not single-path) and uses probabilistic operators, making it well-suited for complex, multi-modal optimization landscapes where gradient-based methods fail. The fitness function is the performance measure analogue.
