📌 What This Lecture Is Really About

Number theory is the mathematical backbone of public-key cryptography. This lecture establishes the foundational tools that make RSA, Diffie-Hellman, and elliptic curve cryptography possible. You will work through divisibility and the GCD, modular arithmetic and its algebraic properties, Fermat's and Euler's theorems (which directly underpin RSA key generation and correctness), and the discrete logarithm problem — the hardness of which is what makes Diffie-Hellman secure. The complexity results at the end tie everything together: integer factorisation, computing Euler's totient, and solving the discrete log are all believed to be computationally intractable for large inputs.

⚠ Exam FocusBe able to: apply Euler's theorem to reduce large modular exponentiations; compute φ(n) for any n; state both forms of Fermat's and Euler's theorems; identify primitive roots and understand discrete logarithm structure; explain why the three hard problems matter for cryptography.

➗ Divisibility

Definition
b divides a (written b | a) if there exists an integer m such that a = mb.

b is called a divisor of a.
Example: 4 | 12 because 12 = 3 × 4 7 | 49 because 49 = 7 × 7 5 ∤ 13 because 13 ≠ m × 5 for any integer m
🔑 GCDgcd(a, b) is the greatest common divisor of a and b — the largest integer that divides both.

The Euclidean algorithm computes gcd efficiently by repeated division:
gcd(a,b) = gcd(b, a mod b) until b=0
🔑 Relatively Primea and b are relatively prime (coprime) if gcd(a,b) = 1.

This is critical: many cryptographic operations require inputs to be relatively prime to the modulus.

🔢 Prime Numbers

Definition
An integer p > 1 is prime if and only if its only divisors are ±1 and ±p.

Any composite integer a > 1 can be uniquely expressed as:
a = p₁^a₁ × p₂^a₂ × ⋯ × pₜ^aₜ
where p₁ < p₂ < … < pₜ are primes (Fundamental Theorem of Arithmetic).
Examples: 12 = 2² × 3 100 = 2² × 5² 315 = 3² × 5 × 7
⚠ Cryptographic ImportanceRSA security relies on the fact that given n = pq (a product of two large primes), factoring n back into p and q is computationally intractable when p and q are ~1024 bits each. The slide notes the largest RSA number factored was 768 bits (232 decimal digits) — achieved with massive distributed computation.

🔄 Modular Arithmetic — Definitions

Definition: a mod n
For integer a and positive integer n, a mod n is the remainder when a is divided by n.

n is called the modulus.

The set Z_n = {0, 1, 2, …, n−1} contains all possible remainders mod n.
Examples: 7 mod 3 = 1 (7 = 2×3 + 1) 11 mod 5 = 1 (11 = 2×5 + 1) -3 mod 5 = 2 (-3 = -1×5 + 2) 25 mod 7 = 4 (25 = 3×7 + 4)
Congruence
Two integers a and b are congruent modulo n if they have the same remainder when divided by n:

a ≡ b (mod n) iff (a mod n) = (b mod n)

Equivalently: n | (a − b)
Examples: 73 ≡ 4 (mod 23) [73 = 3×23 + 4] 21 ≡ 0 (mod 7) [7|21] -5 ≡ 9 (mod 7) [7|(-5-9)? no: 7|14 ✓]
🔑 Key InsightThe (mod n) operator maps all integers to the finite set Z_n = {0, 1, …, n−1}. Modular arithmetic performs all arithmetic operations within this set — this is what allows cryptography to work with fixed-size numbers even when the mathematical operations would normally produce astronomically large values.

📐 Reduction Rules

The three fundamental reduction rules allow reducing before or after operations:

[(a mod n) + (b mod n)] mod n = (a + b) mod n [(a mod n) − (b mod n)] mod n = (a − b) mod n [(a mod n) × (b mod n)] mod n = (a × b) mod n
Why useful? When computing a^k mod n for large k, you can reduce at every multiplication step. This prevents numbers from growing to millions of digits during repeated squaring.

Worked Example: Compute 7³ mod 13

1
7² = 49. Reduce: 49 mod 13 = 10 (49 = 3×13 + 10)
2
7³ = 7² × 7 = 10 × 7 = 70. Reduce: 70 mod 13 = 5 (70 = 5×13 + 5)
✓
7³ mod 13 = 5

⚠ Z_n is a RingBecause Z_n has all these properties (except not all elements have multiplicative inverses), Z_n forms a commutative ring. When n is prime, every non-zero element has a multiplicative inverse — Z_p becomes a field. This is why prime moduli are preferred in cryptography.

🔀 Division in Modular Arithmetic

Additive Inverse
a is the additive inverse of b if:
a + b ≡ 0 (mod n)

Every integer w ∈ Z_n has an additive inverse.
The additive inverse of w is simply n − w.

Example: additive inverse of 3 in Z_7 is 4, since 3+4 = 7 ≡ 0 (mod 7)
Multiplicative Inverse
a is the multiplicative inverse of b if:
a × b ≡ 1 (mod n)

NOT all integers have a multiplicative inverse mod n.

a has a multiplicative inverse in (mod n) if and only if gcd(a, n) = 1 (a is relatively prime to n).
🔑 DivisionDivision by b mod n is defined as multiplication by the multiplicative inverse of b:
a ÷ b ≡ a × MultInverse(b) (mod n)

⚠ RSA ConnectionIn RSA, the private key d is the multiplicative inverse of e modulo φ(n). This requires gcd(e, φ(n)) = 1 — which is why RSA requires e to be chosen coprime to φ(n). The extended Euclidean algorithm computes this inverse efficiently.

⚡ Fermat's Theorem

Fermat's Theorem (Form 1)
If p is prime and a is a positive integer not divisible by p, then:

a^{p-1} ≡ 1 (mod p)
Verify: p=7, a=3 3^1 = 3 3^2 = 9 ≡ 2 (mod 7) 3^3 = 27 ≡ 6 (mod 7) 3^4 = 81 ≡ 4 (mod 7) 3^5 = 243 ≡ 5 (mod 7) 3^6 = 729 ≡ 1 (mod 7) ✓ (p-1 = 6)
Fermat's Theorem (Form 2)
If p is prime and a is any positive integer, then:

a^p ≡ a (mod p)

This holds even when p | a (in which case both sides are 0 mod p).
Verify: p=7, a=3 3^7 = 2187 2187 mod 7 = 3 ✓ (3 ≡ a) Verify: p=7, a=7 (divisible case) 7^7 mod 7 = 0 ≡ 7 mod 7 = 0 ✓
🔑 Cryptographic Use of Fermat's Theorem Form 1 gives us: a × a^{p-2} ≡ 1 (mod p). Therefore, the multiplicative inverse of a mod p is a^{p-2} mod p. This provides an alternative to the extended Euclidean algorithm when p is prime — just compute a^{p-2} mod p using fast exponentiation.
Connection to Form 2Form 2 is derived from Form 1: a^{p-1} ≡ 1 (mod p), multiply both sides by a → a^p ≡ a (mod p). Form 2 is more general as it holds even when p|a.

🌀 Euler's Totient Function φ(n)

Definition
φ(n) = the number of positive integers less than n that are relatively prime to n (i.e., gcd(k,n)=1 for k=1,2,…,n-1).

Formulas

φ(1) = 1 (by definition) For prime p: φ(p) = p − 1 (all 1 to p-1 are coprime to p) For n = p × q (distinct primes): φ(n) = (p−1) × (q−1) For a and b coprime, n = ab: φ(n) = φ(a) × φ(b) (multiplicative)

⚠ RSA KeyFor RSA with n = p×q:
φ(n) = (p−1)(q−1)
The private key d satisfies:
d × e ≡ 1 (mod φ(n))
This is why keeping p, q secret means φ(n) is also secret.

⚡ Euler's Theorem

Euler's Theorem (Form 1)
For every a and n that are relatively prime (gcd(a,n)=1):

a^{φ(n)} ≡ 1 (mod n)

This is a generalization of Fermat's theorem: when n=p is prime, φ(p)=p−1, so it reduces to Fermat's Form 1.
Verify: a=3, n=10, gcd(3,10)=1 φ(10) = φ(2)×φ(5) = 1×4 = 4 3^4 = 81 81 mod 10 = 1 ✓
Euler's Theorem (Form 2)
For positive integers a and n:

a^{φ(n)+1} ≡ a (mod n)

This form is used directly in the RSA correctness proof: encrypt with e, decrypt with d where e×d = φ(n)+1, and you recover a.
RSA Correctness: n = pq, φ(n) = (p-1)(q-1) Choose e,d: e×d ≡ 1 (mod φ(n)) → e×d = k×φ(n) + 1 Decrypt((Encrypt(M))) = (M^e)^d mod n = M^{e×d} mod n = M^{k×φ(n)+1} mod n = M × (M^φ(n))^k mod n = M × 1^k mod n [by Euler's Thm 1] = M ✓
⚠ Fermat vs Euler ComparisonFermat's theorem is the special case where n = p is prime. Euler's theorem generalizes to any n. In RSA, n = pq is composite — so you must use Euler's theorem, not Fermat's, for the correctness proof.

📈 Logarithms in Modular Arithmetic

Ordinary Logarithm (Recall)
If b = aⁱ, then i = log_a(b).

Given a and b, find i. Easy with real numbers.
Discrete Logarithm
If b ≡ aⁱ (mod p), then i = dlog_{a,p}(b).

Given b, a, p, find i.

This is computationally hard for large p.
⚠ Why Discrete Log is HardIn ordinary arithmetic, logarithm is easy because the function b = aⁱ is monotonically increasing. In modular arithmetic, b = aⁱ mod p jumps unpredictably — there is no known polynomial-time algorithm for the general discrete log problem. This hardness is the security basis of:
• Diffie-Hellman key exchange
• ElGamal encryption
• DSA (Digital Signature Algorithm)
• Elliptic Curve Cryptography
🔑 Primitive Roota is a primitive root of prime p if the sequence a¹, a², …, a^{p-1} are all distinct (mod p), generating all non-zero elements of Z_p.

Only integers with primitive roots: 2, 4, pᵅ, 2pᵅ where p is an odd prime.

⚠ DH Key Exchange ConnectionIn Diffie-Hellman: Alice sends gᵃ mod p, Bob sends g^b mod p. The shared secret is g^{ab} mod p. An eavesdropper knows g, p, gᵃ, g^b but must compute a = dlog_{g,p}(gᵃ) — the discrete logarithm problem. For p ~ 2048 bits, this is infeasible.

🏋️ Computational Complexity — Hard Problems

Hard ProblemStatementDifficulty vs FactoringCryptographic Application
Integer FactorisationGiven n = pq, find p and qBaselineRSA security: breaking RSA requires factoring n
Euler's TotientGiven composite n, find φ(n)At least as hard as factoringRSA: knowing φ(n) lets attacker compute private key d
Discrete LogarithmGiven b, a, p, find i = dlog_{a,p}(b)Comparable to factoringDiffie-Hellman, ElGamal, DSA, ECC
Current RecordsThe largest RSA number factored into two primes was 768 bits (RSA-768, 232 decimal digits), achieved in 2009. RSA-2048 is currently considered secure. The best known general-purpose factoring algorithm (General Number Field Sieve) runs in sub-exponential but super-polynomial time: exp(O(n^{1/3})).
⚠ Quantum ThreatShor's algorithm can solve integer factorisation and discrete logarithm in polynomial time on a quantum computer. This would break RSA, DH, and ECC simultaneously. Post-quantum cryptography (lattice-based, hash-based, code-based) is being standardized by NIST to address this future threat.
