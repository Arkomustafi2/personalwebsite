What this course is really about

High Speed Computer Networking covers how data moves between computers at rates of Mbps, Gbps, and Tbps with low latency and high reliability. The course builds from foundational performance metrics (latency, bandwidth, reliability) through switching paradigms, OSI/TCP-IP architecture, and network topologies, up to cutting-edge physical layer techniques like QAM, OFDM, massive MIMO, and beamforming used in 5G and beyond. The connecting theme: every design decision is a tradeoff between speed, cost, reliability, and complexity — and you must know which tool solves which problem at which layer.

⚡ Core Concepts of High Speed Networking (31 Mar 2026)

Definition & 4 Key Characteristics

High speed computer communication refers to the transfer of data between computers or devices at very high data rates — typically Mbps, Gbps, or even Tbps.

① High Data Rate — the primary goal. Throughput measured in Mbps/Gbps/Tbps.
② Low Latency — minimal delay between transmission and reception.
③ High Bandwidth — wide frequency range available for data transmission.
④ Reliability — data arrives correctly and consistently without corruption or loss.

How Latency Can Be Improved (8 Methods)

Latency = propagation delay + queuing delay + processing delay + transmission delay. Each method below targets a specific component.
1
Reduce Physical Distance — shorter distance → lower propagation delay. Achieved via edge servers (servers kept close to user's physical location, holding a cache of data to serve the user faster).
2
Use High Speed Transmission Media — e.g., optical fiber (light-speed propagation, very low delay).
3
Optimize Routing Path — data packets may take inefficient routes across the internet. Use intelligent routing protocols and traffic engineering to reduce hops between source and destination.
4
Reduce Network Congestion — congestion increases queuing delay. Solutions: load balancing, traffic shedding, increasing network capacity.
5
Use Faster Hardware — faster routers, switches, and NICs reduce processing delay.
6
Efficient Protocol Design — protocol overhead adds delay. Streamlined headers and fewer round trips reduce latency.
7
Edge Computing and Caching — process/store data near the end user so fewer requests travel to distant servers.
8
Parallelism and Multiplexing — simultaneous processing of multiple data streams reduces overall wait time.

How Bandwidth Can Be Improved (7 Methods)

1
Use Higher Capacity Transmission Media — optical fiber offers orders of magnitude more bandwidth than copper.
2
Use Multiplexing Techniques — TDM, FDM, WDM, OFDM pack multiple signals onto one medium.
3
Increase Channel Frequency Range — wider frequency band → more bandwidth (Shannon's law).
4
Increase SNR — achieved by better shielding, low noise amplifiers, improved channel conditions. Higher SNR → more bits per symbol.
5
Use Advanced Modulation Techniques — like QAM (64-QAM, 256-QAM) and OFDM encode more bits per symbol.
6
Expand Spectral Availability — use previously unused frequency bands (mmWave in 5G).
7
Reduce Interference and Losses — better shielding, beamforming, interference cancellation.

How Reliability Can Be Improved (9 Methods)

1
Error Detection and Correction — add redundancy bits to detect or fix errors in transmission data (parity, CRC, FEC).
2
Retransmission Protocol — if errors detected, receiver requests retransmission. Protocols: Stop-and-Wait ARQ, Go-Back-N ARQ (Automatic Repeat Request).
3
Use Reliable Transmission Protocols — TCP provides ordered, error-checked delivery.
4
Redundancy in Systems — duplicate links, servers, or paths so failure of one doesn't disrupt service.
5
Improve SNR — cleaner signal → fewer bit errors.
6
Use Robust Transmission Media — fiber optic is immune to electromagnetic interference.
7
Channel Coding Technique — error correction codes (LDPC, Polar codes, Turbo codes) embedded in data.
8
Network Design and Fault Tolerance — mesh topology, redundant routing.
9
Synchronization and Timing — precise clocking ensures receiver correctly samples bits.

Shannon's Capacity Formula (Key Formula)

Shannon's theorem gives the theoretical maximum data rate for any channel.
C = B × log₂(1 + SNR) Where: C = Channel capacity (bits per second) B = Bandwidth (Hz) SNR = Signal-to-Noise Ratio (linear, not dB) SNR (dB) → Linear: SNR_linear = 10^(SNR_dB / 10) Bits per Symbol (QAM): 64-QAM → log₂(64) = 6 bits/symbol 256-QAM → log₂(256) = 8 bits/symbol 1024-QAM→ log₂(1024)= 10 bits/symbol

OSI Model — 7 Layers

The OSI model is a layered protocol framework. Each layer takes service from layers below it and provides service to layers above it.

Layer #NameAddress UsedFunctionTCP/IP Mapping

OSI has 7 layers; TCP/IP has 5 layers. OSI layers 5, 6, 7 are merged into the single TCP/IP Application layer. Functionally there is no difference — OSI is a reference/educational model; TCP/IP is the engineering model actually used.

Encapsulation — How Data Travels Down the Stack

Each layer adds its own header (and trailer at data link). This is called encapsulation. At the receiver, each layer strips its header — called decapsulation.
1
Application layer creates data: e.g., "Hello" (TCP segment)
2
Transport layer adds TCP Header → [TCP Header][Hello]
3
Network layer adds IP Header → [IP Header][TCP Header][Hello]
4
Data Link layer adds MAC Header + Trailer → [MAC Header][IP Header][TCP Header][Hello][Trailer] (trailer used for error checking)
5
Physical layer converts everything to a stream of bits for transmission
Encapsulation structure (transmitting end): ┌────────────┬────────────┬────────────┬─────────┬─────────────┐ │ MAC Header │ IP Header │ TCP Header │ Hello │ Trailer │ │ (Data Link)│ (Network) │(Transport) │ Data │ (Error chk) │ └────────────┴────────────┴────────────┴─────────┴─────────────┘ → Physical layer converts entire frame to stream of bits (010110...)

Why OSI vs TCP/IP?

Engineer's perspective: Works from physical layer. Overhead added at each layer going down, stripped going up. The intuitive model shows this clearly.
User's perspective: Works from application layer downward. TCP/IP is the model actually deployed. OSI is the reference/study model.
OSI Presentation and Session functions (compression, encryption, session management) are handled inside the TCP/IP Application layer — functionally no difference, just different grouping.

🗺️ Network Topologies, LAN, MAN & WAN (Aug 2026)

Network Topology — Definition

Network topology describes how devices (nodes) and communication links are arranged in a computer network — both physically and logically. It directly affects performance, scalability, reliability, and cost.

7 Types of Network Topologies

1. Point-to-Point Topology

Direct connection between exactly two devices (C₁ — C₂). Cheapest from cost perspective, simplest, but not scalable — only two nodes.

2. Bus Topology

All devices connected to a single backbone cable. Simple and low cost, easy to install. Problems: If backbone fails → entire network fails. Data collision occurs → traffic increases → congestion. Reliability↓ Cost↓ Scalability↓. Repeaters can be used to extend segments.

3. Star Topology

All devices connect to a central hub. Easy to manage and expand. Failure of one node doesn't affect others. Weakness: Central hub failure → entire network down. Scalable, reliability better than bus topology.

4. Ring Topology

Devices arranged in a circle. Data travels in one direction. No collision (controlled access). Weakness: Failure of one node can break the network (unless dual ring). Used for backbone support. Not scalable, not reliable.

5. Mesh Topology

Every device has a direct connection to every other device. Very reliable. High degree of redundancy. Weakness: Expensive and complex. Repeaters may still be needed.

6. Tree Topology (Hierarchical)

Star topology in hierarchy — Root → Hub → Devices. Scalable and organized. Root failure affects large sections.

7. Hybrid Topology

Combination of two or more topologies (e.g., Ring + Star, or Star + Bus). Very high scalability and flexibility. Cost varies.

Physical vs Logical Topology

Physical Topology: How devices are actually wired/connected in the real world.
Logical Topology: How data flows through the network — may differ from physical layout (e.g., Ethernet uses logical bus over physical star).

LAN, MAN, WAN, PAN — Coverage & Technical Comparison

1. Local Area Network (LAN)

• Covers small geographic area — home, office, building
• Usually privately owned and managed
• High speed, low latency. Ex: WiFi in your home

Key insight: LAN is not just "small span" — it implies high speed, tight control, local administration, homogeneous network.

Works at: Layer 1 (Physical) + Layer 2 (Data Link)
Devices: Switches, Bridges, Access Points
Addressing: MAC address. Usually no routing.

2. Metropolitan Area Network (MAN)

• Covers a city or large campus
• Connects multiple LANs within a city/big campus
• Often managed by service providers or large organizations
• Medium to high speed

Key insight: MAN is city-scale interconnection — shared infrastructure. Homogeneous network within city.

Works at: Layer 1 (Physical) + Layer 2 + Layer 3 (Data Link + Network)
Devices: Routers, Gateways, ISP Infrastructure
Routing: Dynamic routing protocols
Addressing: MAC + IP

3. Wide Area Network (WAN)

• Covers large geographic areas — country, continents
• Connects multiple MANs and LANs
• Uses public or leased communication links — CISP network, undersea cables
• High latency compared to LAN

Key insight: WAN implies long distance communication; heterogeneous infrastructure; reliance on telecom providers.

Works at: All layers — multihop routing across long distances
Devices: ISP Routers, Backbone Networks, Undersea Cables, Satellite Links
Addressing: IP

4. Personal Area Network (PAN)

Very short range — Bluetooth to the telephone. Range ~10m. Ex: Connecting phone to wireless earbuds.

📡 Physical Layer Techniques & Network Devices (15 Apr + 21 Apr + 29 Apr 2026)

Physical Layer — Purpose

The physical layer is concerned with transmitting raw bits. Its performance is measured by high data rate and low latency.

11 High Performance Techniques for Physical Layer

1
Advanced Modulation Techniques — Higher order QAM (64-QAM, 256-QAM, 1024-QAM). Increases bits per symbol. Tradeoff: high SNR required. The most widely used technique; requires low-noise channel. OFDM is another such technique.
QAM Order → Bits/Symbol: 64-QAM → log₂(64) = 6 bits/symbol 256-QAM → log₂(256) = 8 bits/symbol 1024-QAM → log₂(1024) = 10 bits/symbol Channel condition → Modulation used: Very noisy → BPSK (1 bit/symbol) Moderate → QPSK (2 bits/symbol) Good → 16-QAM (4 bits/symbol) Excellent → 64/256-QAM (6-8 bits/symbol)
2
Channel Coding — Done for error control. Improves reliability, requires fewer retransmissions → lower latency. Codes: LDPC (Low Density Parity Check), Polar code. Used in 5G NR standard.
3
MIMO and Massive MIMO — Multiple antennas at TX and RX. Multiple parallel spatial streams → higher throughput. For massive MIMO: hundreds of antennas used (like in 5G). Improves data rate and reliability due to redundancy in terms of antennas. Reduces latency as data is sent in parallel from each antenna.
4
Beamforming — Focuses signal energy towards a specific user instead of broadcasting in all directions. Improves SNR, reduces interference, enables faster and more reliable transmission.
5
High Frequency Bands — More bandwidth → higher data rate. Tradeoff: short range, high attenuation (can be solved by beamforming). Mainly an issue for microwave communication; at higher frequencies we use separate optical fiber medium.
6
Advanced Waveforms (5G and beyond) — Filtered OFDM, HEMC, FBMC → Reduces latency, reduces band interference.
7
Fiber Optic Communication — Extremely high bandwidth, very low propagation delay. Technology: WDM (Wavelength Division Multiplexing), coherent optical detection.
8
Full Duplex Communication — Doubles spectral efficiency, reduces waiting delay. Both TX and RX transmit simultaneously on the same channel.
9
Synchronization and Timing Optimization — Precise clocking. Reduces jitter and symbol misalignment.
10
Adaptive Techniques — Adaptive modulation and coding (AMC). System dynamically adjusts modulation based on current channel condition. Lets us achieve lower latency.
11
Hardware Level Innovation — High speed ADC/DAC, low noise amplifiers, RF front-end optimization. Allows faster signal processing, lower delay, low latency.

Modern High Speed LAN Technologies

① Modern Ethernet (IEEE 802.3)
Key variants: Gigabit Ethernet (1 Gbps) | 10 Gigabit Ethernet (10 Gbps) | 25/40/100/400 Gbps
Main features: Works over twisted pair (Cat6/Cat7) and fiber. Uses switching. Highly scalable and cost effective. Supports full duplex communication.
Why it dominates: Simple, cheap, extremely fast, backward compatible. Backbone of all modern LANs.
② Fiber-Based Ethernet
Ethernet running over optical fiber. Very high speed (10G–400G), long distance within campus/data centres. Used in: Data centres, university campus, electrical backbone networks.
③ Wi-Fi (Wireless LAN) — IEEE 802.11
Modern standards:
• Wi-Fi 5 (802.11ac) → ~3.5 Gbps
• Wi-Fi 6E (802.11ax) → ~9.6 Gbps
• Wi-Fi 7 (802.11be) → ~30+ Gbps
Features: Wireless connectivity, OFDM, MU-MIMO, beamforming. Supports home, office, mobile computing.
④ Software Defined LAN
Network controlled via software instead of hardware configuration. Used in enterprise networks, smart campuses. Features: Centralized control, Automation, Easy scalability, Integration with cloud.
⑤ Data Centre LAN Technologies
Leaf-Spine Architecture. High Speed Ethernet (25G, 100G, 400G). Features: Very low latency, high throughput, redundant path. Supports: Cloud computing, AI workloads, big data processing.
⑥ Power over Ethernet (PoE)
Ethernet cable carries both data and power. Used in: IP cameras, Wi-Fi access points, VoIP phones.
⑦ Time Sensitive Networking
Features: Deterministic delay, ultra-low latency, real-time communication. Used in: Industrial automation, Robotics, Autonomous Systems.
